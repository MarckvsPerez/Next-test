# Front: team-playground addendum

Rules for this repo. They override the generic ones in `team:front`.

## Stack

- Next.js 16.4.4 (App Router), React 19.3, TypeScript strict, Tailwind CSS v4.
- This is NOT the Next.js in your training data. Before using any Next API, read the relevant guide in `node_modules/next/dist/docs/01-app/` and follow its deprecation notices.

## Rendering and caching

- `next.config.ts` has `cacheComponents: true` and `partialPrefetching: true`. Don't turn them off.
- Cache with the `use cache` directive, and pair every `use cache` with `cacheLife` (`01-getting-started/08-caching.md`). Don't use the old model (`export const revalidate`, `fetch(..., { next: { revalidate } })`).
- `params` and `searchParams` are async: `await props.params`. Type pages and layouts with the global helpers `PageProps<'/route'>` and `LayoutProps<'/route'>` (see `src/app/layout.tsx`). They're generated by `next typegen`, so don't declare them by hand.

## Styles and tokens

- Tailwind v4 has no `tailwind.config.*`. Tokens are CSS variables in `:root` and get exposed in `@theme inline` inside `src/app/globals.css`.
- Use utilities based on tokens (`bg-background`, `text-foreground`). Don't use loose hex colours in components. If a token is missing, ask `designer` for it. You own `globals.css` and you apply the change.
- The site is dark-only (charcoal `#2A2A2A`, silver `#C0C0C0`, red accent `#E10600`). There's a single `:root`, with one value per token, `color-scheme: dark`, and no `prefers-color-scheme` block. Don't reintroduce a light theme without a decision from `designer`.
- The red accent (`--accent`) is only a fill with `--accent-foreground` (white) on top. It's never text, a border or a focus ring: on `--background` it gives 2.89:1 and on `--surface` 2.54:1, below the minimum. The list of elements allowed to use it is in `docs/design/landing.md` §3.
- `themeColor` in the `viewport` of `src/app/layout.tsx` duplicates `--background` (meta tags can't read CSS variables). If the background changes, update both.
- Every animation needs an alternative under `prefers-reduced-motion: reduce`.

## Structure and boundaries

- Import with the `@/*` alias (it maps to `src/*`). Don't use relative paths that go up more than one level.
- Reusable components go in `src/components/`, client hooks in `src/hooks/`, and client or shared utilities in `src/lib/`.
- `src/app/api/*` and `src/server/*` belong to `back`. If a page needs data or a mutation, ask `back` for the function or the Server Action, and import it from `src/server/`.
- Inside `src/app/`, only create `.tsx` and `.css` files. Metadata files such as `sitemap.ts`, `robots.ts` or `manifest.ts` aren't assigned to any role: ask the lead before creating them.
- Use `"use client"` only on the leaf component that needs interactivity, never on a whole page or layout.

## Quality

- Before closing a task: `npx next typegen && npx tsc --noEmit && npm run lint`. The gate runs the same thing.
- Tests run with Vitest + React Testing Library (jsdom). Put test files next to the code they test as `*.test.ts(x)` under `src/`. Use `npm test` to run them once and `npm run test:watch` for watch mode. If a task changes behaviour, add or update its test.
- Vitest can't render `async` Server Components. Test those with E2E tests, not unit tests.
